11 个功能，真实操作展示

Agent 能力

把任务交给 AI，一起把事情做完。

用自然语言交代目标，Snap 结合模型、文件与工具推进任务。你可以先讨论思路，再进入执行；也可以先让它研究并写出计划，确认之后继续。

执行过程持续呈现在会话里。需要补充要求、回答问题、暂停或检查产物时，你始终可以参与进来。

  • Chat 与 Agent，已有讨论可以迁移后继续
  • 计划、权限确认、消息排队、停止与重试
  • 流式回复、工具过程与任务产物

项目管理

每一份工作，都有自己的空间。

把同一份工作的会话、资料、规则和工具放进一个项目。连接已有的本地目录，或从新项目开始，研究、写作和开发都有清晰的归属。

项目事实和长期约定可以持续积累；某次任务的附件与讨论则留在会话里。下一次继续工作时，从已经准备好的项目环境出发。

  • 连接已有目录，或创建新的项目
  • 项目与会话分别组织附件和资料
  • 按项目管理规则、记忆、Skills 与 MCP

Skills 与 MCP

把常用方法，变成随时可用的能力。

把重复使用的工作方法整理成 Skill，在需要的时候直接调用。研究资料、处理文档、运行脚本，都可以沿用熟悉的步骤和交付要求。

通过 MCP 连接外部工具与服务，通过 CLI 使用本机已有的命令行能力。不同项目可以选择各自需要的工具，让每次任务带着合适的能力开始。

  • Skills 启停、导入、更新与文件编辑
  • MCP 服务器配置、连接验证与工具列表
  • 按项目配置命令行集成

外部工具需具备相应依赖、账号与访问权限。

项目记忆

把重要约定，留给下一次。

写作偏好、项目背景、工作中的约定，可以留在可查看、可修改的记忆文件里。比起每次重新解释，从共同积累的背景继续更自然。

Snap 将协作规则与长期记忆分开组织，支持 MEMORY.md 和主题文件。记忆有变化时可以回顾，哪些内容需要保留，由你来判断。

  • 项目规则与记忆分别管理
  • 直接查看和编辑记忆内容
  • 记忆变更提示与会话回顾入口

万物上下文

文件、会话、待办，都能成为下一步的依据。

用 @ 引用文件、& 引用会话、~ 引用 Todo 和日程，用 / 调用 Skill、# 选择 MCP。把具体资料带进问题，让 Agent 清楚这次工作依据什么。

在文档或回复里选中一段内容，可以带着来源继续追问。项目规则、附加目录、历史讨论与探索结果，也能参与下一步；长对话则通过占用提示与压缩继续整理。

  • 文件、历史会话、Todo 与日程引用
  • 选区引用、附加资料与项目规则
  • 上下文占用、分界与长会话压缩

子会话与主会话

把一个大任务，交给几个明确的角色。

把资料研究、方案审阅、代码检查等工作拆成独立子任务。主会话保留整体目标，子会话围绕明确的角色、问题和交付要求开展工作。

父子关系与运行状态可以追踪。收到结论后，继续跟进原来的子会话，让复审与修改沿着已有成果推进。

  • 为子任务指定角色、目标与交付要求
  • 查看父子会话关系与运行状态
  • 继续已完成或已中断的子会话

探索能力

想岔开研究一下，随时另开一条思路。

从某条回复开始探索，继承截至这条回复的上下文，单独追问一个假设、一处风险或另一种解法。主任务依然保持原来的讨论节奏。

探索中出现值得保留的结论，可以通过引用带回主会话。你可以先把问题想清楚，再决定哪些内容进入下一步。

  • 从选定回复创建探索会话
  • 继承分叉前的上下文，展开旁支讨论
  • 将探索引用带回主会话

带回的是探索引用；文件修改仍需单独检查。

Obsidian

让知识回到你自己的 Markdown 文件里。

连接已有的 Obsidian Vault，在 Snap 里浏览文件树、创建笔记和目录，直接编辑原有 Markdown。资料、图片和双链继续留在熟悉的知识结构中。

授权之后，让 Agent 结合笔记工作，也可以将研究和任务成果写回知识库。会话里的阶段性结论，逐渐变成下一次能用上的资料。

  • 连接已有 Vault，浏览与创建笔记
  • Markdown 编辑、图片与双链
  • 授权 Agent 读取与写入知识库

支持 Markdown 文件工作流；不包含完整的 Obsidian 插件体系。

Todo / 日历 / 定时任务

下一步和下一次，都安排好。

把讨论中的后续动作放进 Todo，设置优先级、截止时间、项目和标签。需要开始工作时，从待办明确启动 Agent，并把执行会话关联回来。

用日历安排时间，用提醒跟进事项；对需要重复进行的工作，配置单次或周期任务，选择项目与模型，再从运行记录检查每次执行。

  • Todo 状态、优先级、截止时间与会话关联
  • 日程安排与到期提醒
  • 单次、每日、每周等周期任务与运行记录

提醒与定时执行依赖本机 Snap 运行。

文件、改动与终端

边做边看，把交付物放在眼前。

文件树和预览就在任务旁边，文档、代码和产物可以随时打开检查。Markdown、PDF 与 Office 文件的预览，让讨论和阅读留在同一个工作环境。

修改代码时查看 Git Diff，在已授权仓库中选择 worktree；需要运行、调试或启动服务时，打开可见终端继续。写了什么、改了哪里、运行结果怎样，都有直接入口。

  • 文件树、文档预览与选区引用
  • 代码编辑、Git 改动与 worktree
  • 可见终端与本机命令执行

Office 以预览和内容提取为主；复杂格式需回到原应用核对。

执行轨迹与 AI 说明

每一步做了什么，为什么做，都有迹可查。

输入、模型与工具分成三条泳道，沿着时间线查看一次任务怎样推进。可以搜索步骤、筛选异常，也可以打开概述、参数、结果、上下文、Schema 和计时，核对原始过程。

想进一步理解某一步时，打开 AI 说明。模型结合任务、公开操作与返回结果，用大白话解释做了什么、可能是为了什么；说明保留在步骤旁，原始证据也随时可看。

  • 三泳道可视化、顺序与真实耗时
  • 步骤搜索、异常筛选与六类详情
  • 按需开启模型说明，成功结果缓存

AI 说明默认关闭，产生额外模型用量；Agent 执行中排队。目的解释属于推测，历史缺失信息会标记为不可用。

常见问题

Snap 和普通聊天窗口有什么区别？

Snap 把项目目录、规则、记忆、工具和工作产物组织到桌面工作台中。Chat 适合讨论与问答，也能使用已配置的工具；Agent 则围绕任务连续执行，并提供文件、终端与轨迹等检查入口。已有 Chat 可以迁移到 Agent 继续。

AI 说明会一直调用模型吗？

不会。轨迹里的 AI 说明默认关闭，需要时才开启，并产生额外模型用量。有 Agent 任务运行时，说明请求会排队；成功说明会缓存。它基于公开的任务、操作和结果解释步骤，目的属于推测，原始详情仍可直接核对。

定时任务需要一直开着 Snap 吗？

需要。提醒和定时执行依赖本机 Snap 运行；配置好项目、执行内容与时间后，可以从运行记录查看每次任务的结果。

我的笔记和资料放在哪里？

项目文件、会话与记忆保存在本机。Obsidian 接入直接使用 Vault 中的 Markdown 原文件，授权后 Agent 可读写相应内容。调用外部模型、MCP 或其他服务时，任务所需内容会发送到相应服务，具体范围取决于任务和配置。

这些动态演示展示的是什么？

动态演示录制自更名前版本的实际界面，展示对应功能的操作与入口。部分等待时间经过剪辑或加速。演示可随时暂停，也可以放大查看细节。
